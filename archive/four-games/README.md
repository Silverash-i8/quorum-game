# CELL OUT

A Jackbox-style engineering business game for the ELEC3030 Engineering Business Game assignment.
One laptop shows the shared **host screen**; every player joins from a **phone** by scanning a QR code.
3 or 4 companies, five rounds (2027 to 2031), about 45 minutes.

Each player runs a battery-pack company. Cheap unaudited cells and ethical shortcuts make money early,
but the winner is the highest **Enterprise Score**: net worth + Reputation + Sustainability + patents and trade secrets.

## Four games, one server

The same server now hosts four games. Open `http://localhost:3000/` and pick one.

| Game | What it is | Seats | Status |
| --- | --- | --- | --- |
| **Cell Out** (`/host`) | Run a battery company for five years | 3 or 4 (runs 2 to 6) | The submission candidate. Printed instructions and datasheets in `docs/` |
| **Chain Reaction** (`/chain/host`) | Four links of one supply chain with hidden stock and delayed deliveries | 4, bots fill empty seats | Playable. Tested by bots and automated browsers |
| **Quorum** (`/quorum/host`) | Four directors with private reports, private bonuses and secret votes | 4, bots fill empty seats | Playable. Tested by bots and automated browsers |
| **Patent Pending** (`/patent/host`) | Sealed-bid auctions for patents, quota, suppliers and data, then licensing | 3 or 4, bots fill up to 3 | Playable. Tested by bots and automated browsers |

The three smaller games have their rules on the lobby screen. They do not have printed Player Instructions or datasheets yet.

## Start it

**Windows:** double-click `start.bat`. It uses Docker if Docker Desktop is running, otherwise Node.js.
It finds the laptop's Wi-Fi address, starts the server and opens the host screen.

**By hand, with Docker:**

    docker compose up --build -d
    # open http://localhost:3000/
    docker compose down          # to stop

**By hand, without Docker** (Node.js 18 or newer, no packages to install):

    node src/server.js

Then on the laptop open `http://localhost:3000/` and choose a game. Players scan the QR code, type a name and join.

## Getting phones connected

Phones must be able to reach the laptop:

- **Same Wi-Fi at home, or a phone hotspot:** works as it is. The QR code points at the laptop's address.
- **University Wi-Fi (eduroam):** devices usually cannot see each other. Put the laptop and the phones on one
  phone's hotspot, or turn on Windows *Mobile hotspot* on the laptop and have phones join that. No internet is needed.
- **Windows Firewall:** the first time, allow access when Windows asks (for Docker Desktop or Node.js) on private networks.
- **Wrong address in the QR code:** on the lobby screen press *Change the address* and type the laptop's
  address, for example `http://192.168.1.20:3000` (run `ipconfig` to find it).
- **Public address (phones on any network):** double-click `start-public.bat`. It runs the games in Docker with a free
  Cloudflare tunnel and prints an `https://....trycloudflare.com` address, also saved in `public-address.txt`.
  Open that address on the laptop and host from it. Needs Docker Desktop running and an internet connection.
  The address changes on every start.

## What is in the box

| Path | What it is |
| --- | --- |
| `src/engine.js` | All the rules, as pure functions. Numbers are in the `R` object at the top. |
| `src/content.js` | Text of the market, risk and dilemma cards and the actions. |
| `src/bots.js` | Practice bots (four styles) used to fill seats and for the balance simulation. |
| `src/server.js` | Web server: rooms, joining, long-polling, timers, saving games, CSV report. No dependencies. |
| `src/games/` | The three smaller games: `chain.js`, `quorum.js`, `patent.js` (rules, content and bots), on the shared skeleton `base.js`. |
| `public/g/` | Host and phone screens for the smaller games: shared `kit.js`, one file per game. |
| `public/` | Host screen (`host.html`), phone controller (`play.html`), styles, fonts, QR library. |
| `public/instructions.html`, `public/datasheet.html` | Printable Player Instructions and blank Datasheet, generated by `scripts/build-docs.js` from the live rules. |
| `docs/` | PDF copies of the Player Instructions and ten blank Datasheets, for Minerva. Also `THREE-MORE-GAME-IDEAS.md`: three further game concepts (not built). |
| `test/` | Unit tests, server tests, a browser end-to-end test and the balance simulations. |

## Pages

- `/host` the big screen. `/play` the phone controller. `/j/CODE` the short join link in the QR code.
- `/instructions` and `/datasheet` (add `?copies=10` for the full set) are printable.
- At the end of a game the host can **Download the game report**: a CSV of every company's yearly figures,
  which is the evidence the Game Overview needs from a test-play.

## Checks

    npm test                 # 31 tests across all four games: rules, randomised games, junk input, server, privacy
    node test/ethics.js 800  # evidence table: score by how often a company takes the dilemma shortcut
    node test/sim.js 3000    # balance: one of each strategy
    node test/mix.js 4000    # balance: random strategy in every seat
    python3 test/e2e.py      # full game through real browsers (needs Playwright for Python)
    python3 test/e2e-games.py     # the three smaller games through real browsers
    node test/sim-chain.js 500    # bot simulations: also sim-quorum.js and sim-patent.js

If you change a number in `src/engine.js`, run `npm test`, then `node scripts/build-docs.js` so the printed
instructions match, and bump `R.version` (saved games from older rules are dropped).
